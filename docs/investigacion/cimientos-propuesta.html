Dónde falla: nuestra oportunidad

No hay conductor

Cada herramienta vive aislada y vuelve a preguntar todo. El usuario es el pegamento.

Backend débil

Sin RLS probadas, migraciones, colas ni rate limiting. Apps que se ven bien y filtran datos.

Seguridad como checklist

Nadie conecta amenazas → permisos → políticas → tests.

Frontend sin medir

Accesibilidad, Core Web Vitals y anti-"AI slop" quedan como opinión.

Termina en el plano

the-architect no construye, no publica, no opera.

Specs que se pudren

El plano deja de describir el sistema real tras el primer cambio.

30 minutos en silencio

La generación parece colgada.

Asume desarrollador

Excluye al dueño de negocio y al principiante.

✓

Terminado (v1): un principiante lo usa de la idea al deploy y sale un SaaS real con auth, base de datos, API, frontend con design system y auditoría de seguridad aprobada.

03

El flujo: 9 fases con puertas

FASE 0Contexto

Lee la carpeta de contexto o el repo existente antes de preguntar.

Puerta: mapa de lo que ya se sabe
FASE 1Descubrir

Una pregunta por turno, diciendo qué cambia según la respuesta. Detecta el nivel del usuario.

Puerta: tipo de producto confirmado
FASE 2Recortar

Tres versiones de la idea (mínima, recomendada, soñada). Al menos 5 Non-Goals.

Puerta: MVP firmado
FASE 3Diseñar

Tipo × perfil de stack × capacidades. Atributos de calidad, C4, datos, contratos de API, matriz de permisos, mapa de amenazas, DESIGN.md y EXPERIENCE.md.

Puerta: ninguna dimensión en silencio
FASE 4Puertas

Máximo 5 preguntas con opción recomendada, pre-mortem, checklists de calidad de requisitos, validador por script y validador IA independiente.

Puerta: 0 dudas, 0 BLOCKER
FASE 5Planear

Grafo de tareas en olas paralelas. Cada paso con 4 campos y su test.

Puerta: plan validado
FASE 6Construir

El conductor ejecuta e invoca el kit de cada capacidad con el contrato resuelto. Subagente por tarea + revisor. Hooks de políticas activos.

Puerta: cada paso en verde + tag
FASE 7Verificar y publicar

Auditoría común: seguridad, RLS con la app corriendo, accesibilidad, rendimiento, anti-slop, SEO. Preview → smoke → producción con tu confirmación.

Puerta: gate global en verde
FASE 8Operar

Cambios como deltas sobre specs vivas, detector de desvío en CI, loop de mantenimiento.

Puerta: spec = sistema real

Cada fase larga muestra avances cortos. Nunca 30 minutos en silencio.

04

Las capas que hacen "bases sólidas"

Frontend

  • Design system generado desde el brief, con semilla para que no salga todo igual
  • Exporta a variables CSS y tema de Tailwind
  • Reglas versionadas: accesibilidad, rendimiento, animación, anti-slop, componentes, estado
  • Cada componente con sus estados: cargando, vacío, error, datos extremos
  • axe + Playwright + Lighthouse CI: LCP < 2,5 s, INP < 200 ms, CLS < 0,1

Backend y API

  • Contrato primero (zod/OpenAPI), validación en la frontera
  • Un solo formato de error, paginación, versionado
  • Rate limiting, webhooks idempotentes, colas para lo lento
  • Tests de contrato contra la API real

Datos

  • Migraciones con vuelta atrás, índices justificados, seed coherente
  • Dinero en enteros, borrado decidido, retención de datos personales
  • Introspección en solo lectura con hook guardián (también vía MCP)

Seguridad

  • Amenazas por capacidad → matriz de permisos → políticas RLS generadas
  • Test que prueba que el cliente A no ve datos del B
  • Policy packs en hooks: auth, pagos, uploads, SQL, CORS, headers, secretos en VITE_*
  • Auditoría al editar, al terminar el turno y en cada commit

Deploy y operación

  • Entornos local / preview / producción con variables por entorno
  • CI con las puertas; migraciones antes de promover
  • Smoke funcional, monitoreo de errores, rollback
  • Hosting elegido también por términos de uso comercial

LatAm

  • Pagos: Wompi, Mercado Pago, PSE, Nequi, Stripe
  • Habeas Data (Ley 1581) y facturación electrónica como checklist
  • WhatsApp como canal nativo
